# ORPHEUS development workflow

- Target build is Overwatch 1.74.0.0.104319. Finish the Soldier: 76 and Practice Range acceptance group first, then reuse the same checks for the next hero or map. Prefer evidence from the target build and small changes to shared mechanisms.
- Unattended tasks work on server code, data tools, tests, and documentation. Leave game startup, game controls, and client acceptance to the user unless the user explicitly authorizes a separate session.
- Keep each completed change focused. Inspect the working tree, run the relevant tests and checks, and review the staged diff. Update `CHANGELOG.md` in the same commit with the change, test results, client acceptance, and remaining issues. Use an English Conventional Commit such as `fix: retire obsolete body respawn timers`.
- Keep the active development branch `main`. The intended sync destination is `origin/main` at `https://github.com/leafall903/ORPHEUS.git`. The inherited server remote is `upstream`. Preserve existing history, check the destination and use ordinary fast-forward pushes. Keep the GitHub repository private under the latest user instruction.
- Before the first push, audit **every Git object reachable from the branch**, including historical files and commit metadata. Before later pushes, audit all outgoing commits and objects. Leave credentials, logs, captures, profiles, generated binaries, local caches, and unapproved third-party game assets or data off GitHub. A pattern in `.gitignore` affects untracked files only.
- The inherited local history contains tracked third-party assets, build artifacts and resource keys. Complete the publication audit and resolve the history and redistribution constraints before sending that history. Keep the original local commits. Obtain explicit direction before publishing a differently filtered history or overwriting any existing remote history.
- After a tested commit and a successful publication audit, push `main` to `origin/main`. If authentication, the audit, branch protection or a non-fast-forward blocks the push, preserve the local commit, record the cause and continue local development. Avoid force pushes, remote deletion, history overwrites, automatic releases, and automatic version bumps.
- At handoff, report the project status, branch, latest commit, changelog, test results, client acceptance status, and GitHub sync result.
