Collision provider read tape v1 — explicit in-memory external-read boundary (M0.8)

Scope and use

ow174/game/collision_tape.py records and replays the existing CollisionProvider.poll
contract. It does not change collision.py, Match, GameServer, default providers,
asset loading or gameplay. Nothing records by default, writes a tape, creates a
socket, runs a game, starts a loader during replay or substitutes geometry.

This is a collision-read boundary, separate from environment_tape.py's six clock
and entropy reads and from native_replay.py's body-script-only contract. It does
not capture root events, packet order, match state, commands, contacts held by a
Mover, transport effects or battle outcomes. Successful consumption is not proof
of complete server or native game replay.

  from ow174.game.collision import AsyncCollisionProvider
  from ow174.game.collision_fingerprint import WorldRegistry
  from ow174.game.collision_tape import RecordingCollisionProvider, ReplayCollisionProvider

  registry = WorldRegistry()
  recording = RecordingCollisionProvider(AsyncCollisionProvider(), registry)
  # Supply recording via the existing Match(..., collision_provider=recording).
  # Drive explicitly controlled operations; stop them before ending the interval.
  tape = recording.finish()
  recording.assert_complete()

  replay = ReplayCollisionProvider(tape, resolver=registry.resolve)
  # Repeat precisely the same poll calls, in order, through the same provider interface.
  replay.assert_complete()

A single recording or replay provider can be shared by multiple matches. All of
their polls enter one sequence; a provider factory can explicitly return that
same wrapper. The tape neither groups by map nor searches ahead for a matching
key. An outer root journal can record recording.read_count / replay.position
before and after each root. Cross-boundary order with clocks/entropy requires the
outer journal; two completed independent tapes alone do not establish that order.

The registry retains each actual World seen in a Ready source result. In another
process the caller must explicitly materialize the intended real assets and call
registry.register(world). An explicit resolver callback may also be supplied;
every returned World is fingerprinted again by replay before consumption. No
resolver means no replay, and an unknown, altered or wrong asset permanently
fails. A flat World cannot satisfy a recorded World containing a wall or props.
An intentionally recorded artificial flat fixture remains a flat fixture.

Tape format

The detached Python value has exactly these fields:

  schema: "ow174.collision-read-tape.v1"
  build: "1.74.0.0.104319"
  scope: "collision-provider-reads-only"
  reads: list of rows in actual poll invocation order
  end: {"seq": read_count, "status": "complete"}

Each row has exactly:

  seq: an exact integer, from 0 without gaps
  operation: "poll"
  key: {
    "map_guid": uint64,
    "name": exact supplied text, including an empty string,
    "mode": None or uint64,
    "mode_identifiers": sorted unique uint64 identifiers
  }
  result: {
    "status": "pending" | "ready" | "unavailable",
    "error": exact error text for unavailable, otherwise "",
    "asset": a World descriptor for ready, otherwise None
  }

GUIDs are ordinary exact Python ints in this in-memory format. bool is rejected
in place of int, and all GUIDs must be in [0, 2**64). Extra/missing fields,
non-list rows or identifier collections, duplicate/out-of-order identifiers,
wrong sequence numbers, unknown states, malformed descriptors and missing or
incomplete end markers are rejected. All rows are validated during replay
construction and copied into immutable internal records. Later edits to the
original dict cannot alter a replay.

The derived identifiers come from the current props.mode_identifiers(mode). Both
recording and replay compare them along with every supplied argument. Recording
also checks that the identifiers do not change during the source poll. This is
the canonical provider contract; an arbitrary custom source with hidden alternate
filtering must expose its resulting exact World, which is still fingerprinted.
The model and canonical mode table must not be concurrently mutated.

World identity and complete static field coverage

ow174/game/collision_fingerprint.py computes a materialized static-asset identity.
The descriptor has exactly schema, sha256, model_sha256 and cache_version.
schema is "ow174.collision-world.v1"; cache_version is collision.VERSION.
Both digests are lowercase 64-digit SHA256 values.

The geometry digest covers all supported static representation, including fields
which can influence ground probes, ray tests, sweeps, broadphase and contacts:

- World: name, data (triangle corners and stored normals/plane), masks, surfaces,
  grid with per-cell triangle order, large, lowest and large_tuples.
- StaticWorld: shapes in their original sequence, huge and grid lists containing
  stable shape references. Repeated shape objects remain aliases.
- StaticShape: geometry reference, kind, frame, matrix, inverse, absolute, order,
  mask and fat_low/fat_high. Prop transformations and proxy ordering are covered.
- Hull: centroid, vertices, planes, faces, half-edge topology and mask.
- MeshShape: vertices AND raw vertices used by sweeps, scale/inverse_scale, mask,
  corners AND wing indices, per-triangle masks/surfaces, bounds, grid, large,
  low/high and kind.
- Sphere: centre, radius, mask and kind.
- Capsule: a, b, radius, mask and kind.

Geometry sharing uses deterministic first-seen reference numbers. Native object
addresses are used only to recognize aliases while traversing; neither addresses
nor repr are hashed. Lookup grids use sorted coordinate keys; sequence order and
reference sharing remain explicit. Static derived grids/bounds/AABBs are hashed
as actually stored, not silently discarded because they could be reconstructed.

The canonical encoder distinguishes bool, int, float, bytes, text, tuple, list,
array typecode/itemsize and dict structure. Python floats retain IEEE binary64
bits, including -0.0. Array floats retain their stored IEEE bits and canonical
byte order. NaN and infinity are rejected. Exact supported classes and instance
field whitelists are required; subclasses or unknown extra fields fail instead
of being omitted from an apparently complete identity.

The model digest binds the relevant source bytes and the representation includes
query grid layout constants. See MODEL_FILES in collision_fingerprint.py for the
exact manifest. This is a supported-version identity, not an assertion that a
runtime monkey-patched physics implementation is covered by source-file hashes.

Query caches and mutation constraints

World.columns, MeshShape.cache/boxes and cached Triangle.sides are lazy pure
derivatives. Their occupancy and LRU order do not define an asset. The helper
validates every present cache entry against its static source data, using fresh
temporary Triangle objects where necessary. It does not call the original
World.column/query or MeshShape.query/triangle methods and does not warm, clear
or rewrite the source object's caches. Corrupted or unsupported cached data is
rejected. Warming legitimate query caches preserves the asset identity.

World.lock must be the supported native lock type and is not serialized. Its
snapshot acquisition is nonblocking; an already-held lock fails fingerprinting
instead of waiting or invoking an arbitrary replacement context manager. Mover bodies,
contact manifolds/GJK caches, command history and other live simulation state
are outside this static asset identity; a complete match snapshot must capture
them separately. Callers must stop concurrent World mutation while fingerprinting
or registry resolution. This module does not provide a live mutation barrier.

Fingerprinting is deliberately thorough and can be expensive on real maps;
replay verifies a resolver's result even when the resolver is a WorldRegistry.
Use this explicit boundary in a controlled offline harness. It does not establish
a low-latency live-server recording mode or change the default game lock paths.

The World object does not retain the original .col header/source fields or raw
cache bytes. Therefore this descriptor identifies the fully materialized static
World, not the provenance or byte identity of its source cache file. A source
manifest should separately retain the real .col byte digest/version and canonical
data manifests. The accompanying read-only real-cache validation report records
both cache-file SHA256 and World descriptors. File version or map GUID alone is
never accepted as a substitute for geometry verification.

Permanent faults and completion

The source is called exactly once for each successful recording poll. A source
exception, invalid call/result, fingerprint error, mode-table change, reentrant
poll/finish or read after finish permanently stores the first CollisionTapeError.
Interruptions such as KeyboardInterrupt are re-raised but still mark the wrapper
faulty. Neither recording finish() nor assert_complete() can later succeed after
the caller catches such an error.

Replay advances only after the exact key matches and any Ready asset resolves
to verified content. Mismatch, unknown/mutated asset, resolver failure, reentrant
resolution, exhaustion or early assert_complete() permanently faults the replay.
Later correct-looking polls cannot repair it or advance the position. The first
fault remains available through fault and is raised by assert_healthy() and
assert_complete(). A normally returned server loop, a consumed last index or a
caught exception is never sufficient evidence of completion.

finish() explicitly ends a healthy recording and returns independent data;
repeated finish() exports do not share mutable rows. assert_complete() on a
recorder requires finish(). On replay it requires a healthy tape consumed exactly
through its end marker. A premature completion check is fatal, not a progress
poll. read_count / position / remaining are progress information, not proof.

One RLock serializes each complete wrapper read. Reentrant operations fail rather
than generating ambiguous order. Concurrent callers are recorded in actual lock
acquisition order; replaying that order does not reproduce thread scheduling.

No disk output, credentials, automatic retries or real-world asset fallback are
part of this format. The end marker denotes an explicit recorded interval, not
authentication of a caller-supplied dict. Missing asset material or missing root
and state evidence must remain an incomplete full-server replay claim.

Verification

  .venv/Scripts/python.exe -B -m unittest discover -s tests -p test_collision_tape.py
  .venv/Scripts/python.exe -B -m unittest discover -s tests -p test_collision_fingerprint.py
  .venv/Scripts/python.exe -m ruff check ow174/game/collision_tape.py ow174/game/collision_fingerprint.py

Dedicated tests cover shared multiple-match order, every key component, all three
states, detached exports, strict malformed data, sticky mismatch/exhaustion/less
reads, swallowed/reentrant source and resolver faults, interruptions, unknown or
altered assets, rejected flat substitution, field-level geometry changes and
legitimate cache warming. Real-map verification is a separate read-only report;
unit tests use explicitly constructed geometry and never start a game or socket.

Validation at this implementation boundary: 16 tape tests and 12 fingerprint
tests passed. work/collision_fingerprint_real_cache_validation.json separately
records read-only checks of 0688, 07E2 and 070D v5 caches (the last includes Sphere
props). Cold, warmed and independently loaded copies had identical descriptors;
changing shape.order changed the digest and restoring it restored the identity.
The cache bytes were unchanged. Single fingerprint observations on this machine
were approximately 0.69 s, 2.40 s and 1.15 s respectively; these are observations,
not latency guarantees. Replay can fingerprint again after registry resolution.
